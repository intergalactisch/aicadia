# Resolve the Multiplayer foundation from first principles

> **Role / side:** current Multiplayer decision and research plan / development side.
> **Authority:** owns the dependency order, recording surfaces and evidence gates for
> the active first-principles Multiplayer grill.
> **Excludes:** accepted game behavior, production implementation and experiment
> verdicts; those remain in `game/docs/`, a later accepted build plan and `dev/lab/`.

## Outcome

Root and User reach a shared, scenario-complete Multiplayer foundation for one
persistent Agent-played World. The result states the ordinary player rhythm when
work is independent, conflicting, multi-subject, remotely caused, noticed after
change, recovered after disconnect or deliberately coordinated across Agents.

The User has required a reset from first principles in which everything is
multiplayer and has accepted one World-change lifecycle for every capability call
that may change state. Neither User nor Agent chooses a procedural mode. Only Agents
may understand and author the exact complete final state of a large group of changes;
World may bound, structurally route, validate and settle but never decide semantic
grouping or mechanically combine meaning.
The recursive candidate is now falsified as a universal foundation: World cannot
know semantic grouping and Aicadia cannot launch or depend on additional BYO Agent
inference. The current work pressures attributable World-history, optional
same-invocation handoff, cooldown and previously Agent-authored deterministic
behavior before deriving another User choice. The complete outcome remains an
accepted or explicitly rejected five-year recommendation with no hidden build or
scale claim.

## Non-goals

- No production code, schema, migration, API, MCP public text or operation changes.
- No new lab until one unresolved factual risk could change the next product choice.
- No generic World-change package, proposal board, notification broker or scale
  infrastructure is selected merely to make the design feel complete.
- No spatial decision from the parallel spatial thread is reopened or duplicated.
- No claim that retained local fixtures prove production or million-User capacity.

## Alignment

### Strategic

Multiplayer is not a later feature: it determines whether exploration, creation and
settlement can remain one coherent shared World when millions of independent Agents
act and crowds converge. Choosing the universal operation semantics first prevents a
transaction, actor, shard or collaboration ceremony from silently deciding the game.
The next risk after the conceptual foundation is one narrowly chosen real seam, not
implementation of the complete future architecture.

### Tactical

Work walks one dependency at a time:

1. decide whether every state-changing capability call uses the same World path,
   with one call as ordinary play and simultaneous calls considered together;
2. apply that answer to independent facts, multi-subject consequences, hot subjects,
   remote Actions, observation/reconnect and explicit cooperative operations;
3. identify and research only facts the repository and existing sources cannot
   answer;
4. record accepted, rejected, corrected and deferred choices in the Area, active
   concept and concept log; and
5. synthesize the smallest technical contract and exact evidence still required.

The grill asks one question per User turn. A material answer updates the active
first-principles record and current period log before the next question. The
Multiplayer Area gains only accepted current synthesis; unaccepted recommendation
stays in the concept record.

### Technical

This plan changes documentation and planning state only. Candidate technical claims
must name logical dependency scope, atomic state and Activity, idempotency, authority,
privacy, hot-subject admission, quiet-subject isolation, delivery loss, authorized
refetch, host behavior and the difference between semantic, PostgreSQL, protocol and
Agent evidence.

If a lab becomes necessary, this plan returns to `draft` with one concrete fixture,
real-versus-simulated seam map, bounded cost and dependency-ready task before any
executable artifact is added. A production build always requires a separate accepted
plan through World, PostgreSQL, HTTP, MCP, tests, documents and operations.

  latency — User clarification, 2026-08-21.

  later arrivals cannot extend. Every involved Entity then receives a bounded
  cooldown so its new state cannot be changed again immediately. Neither phase is a

- A state-changing attempt during Entity cooldown returns current settled state and
  remaining time immediately and is never queued or automatically executed later.
  Reads and unrelated play continue; a later mutation needs another explicit Agent
  call — User acceptance, 2026-08-21.
- Every bounded Agent submission that can produce a durable World result uses the
  common lifecycle; pure reads, delivery hints and private Agent reasoning remain
  outside it. This accepts no universal request term, storage table or result payload

- One host-independent Aicadia realtime distribution capability on its deployed
  domain provides default Multiplayer attention during explicitly active play.
  Compatible ChatGPT-like Apps, Claude-like Apps, terminal clients and browsers are

  MCP-only and delivery never invokes or resumes them. Current Place cannot be the
  universal watch because a Character may validly play without one. Exact public
  transport, host adapters, structurally grounded watch set and protocol remain
  open — User acceptance after correction, 2026-08-21.
- Every World manipulation runs through one tick-based system: request → short
  per-subject tick (also for a solo request) → one input applied as authored, or
  several interacting inputs resolved by one content-blind chosen, still-connected
  requesting Agent that receives the whole set → state plus one attributing
  Activity → cooldown → interest-based notice. The chosen Agent is the core
  substitute for an MMO rule engine; the request carries nothing about other
  players; the core path relies only on ordinary MCP tool calls across Claude Code,
  Codex CLI, ChatGPT-like Apps, OpenCode and similar hosts — User acceptance and
  correction, 2026-08-21.

### Candidate investigation ladder after the authority choice

This ladder is planning direction only. It authorizes no lab, external model call or
runtime change until a proportional experimental plan is written and accepted.

1. **Player and Agent contract.** Specify one ordinary action, one real collision,
   what each source player has confirmed, what the selected Agent may decide, the
   exact in-World update a player may hear and the fallback when no combined result
   arrives. Done when no step requires World semantic judgment or unconfirmed state.
2. **Real BYO-Agent interaction over a simulated World seam.** Return a bounded typed
   collision result after the Agent's first tool call. Test whether the same explicit
   invocation continues, whether the Agent narrates the crowd naturally, whether it
   calls the follow-up operation and whether it returns one exact authorized state.
   This proves only host continuation, Agent comprehension, presentation and measured
   latency for the exercised host/model.
3. **Deterministic state machine.** Simulate one ordinary action, compatible and
   contradictory contributions, timeout, disconnect, duplicate delivery, cooldown,
   thousands of offers on one exact fact and quiet unrelated work. Prove bounded
   admission, deterministic selection, idempotency, atomic state/history and local
   overload without claiming database or Agent behavior.
4. **Local MCP integration.** Join the real interaction from step 2 to the state
   machine behind experimental tools. Test canonical fallback, reconnect and hostile
   proposal text. Keep the World seam simulated and record that limitation.
5. **PostgreSQL contention.** Only after the game loop survives, replace the state
   seam with real PostgreSQL coordination for one hot exact fact and many quiet facts.
   Measure locks, queue bounds, p95 latency, rollback and recovery; do not claim
   production or million-User capacity from a local run.
6. **Decision.** Accept, revise or reject the mechanic from the combined GX, Agent,
   deterministic and database evidence. Only an accepted behavior may then evolve
   `game/docs/` and receive a production build plan.
