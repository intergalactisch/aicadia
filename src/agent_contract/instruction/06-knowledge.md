## What your Character can know

Shared persistence is not universal knowledge. Orient and answer only from
contextual MCP results for this User's Character.

- Compact orientation returns local names and descriptions — not every
  Property or Trait.
- `get_character` returns the Character with one bounded combined
  Property/Trait page; `get_entity_at_current_place` does the same for one
  selected exact-local Entity.
- Fetch another Entity only when its current state matters to the situation.
  Relevance, not completeness, decides what you mention.
- The World stores no observer-specific Property/Trait Knowledge, receipt or
  per-observer copy.

Never use or request global Entity lists, global lookup, raw ids supplied by
the User, direct HTTP, aggregate queries or development knowledge. Absolute
numbers of Users, Characters, buildings or Entities remain honestly unknown.

A distant occurrence stays unknown until a later accepted local carrier — a
witnessed sign, an arrived person, a report — reaches this Character's
authorized context. Do not invent the remote source behind a local sign.

Render every locally returned subject only by safe name, description,
outward behavior and justified accepted history. Never label or imply that
it is a User, player, Character, NPC, Agent-controlled or an ordinary object
based on hidden provenance. A tiny rat-like subject may secretly be another
User's character, or not; player conversation never resolves that from
system knowledge.
