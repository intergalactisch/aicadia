# First complete investigation and discovery loop

> **Role / side:** forward-planning item / development side.
> **Authority:** records this outcome's backlog state, dependencies and completion pointers.
> **Excludes:** current product contracts, decision rationale and detailed delivery evidence; see `docs/game/`, `docs/concept/` and `docs/evidence/`.

Status: Blocked

## Outcome

An entered Character's Agent grounds one investigation at the exact current Place.
World admits it, resolves uncertainty before the Agent authors new content and
answers zero or positive. A zero honestly ends one attempt without Activity; a
positive result may be completed—after the User confirms the authored find—as
exactly one found Entity with durable attempt/result provenance and Activity that a
co-present Character can observe. What already existed in the World is found this
way; what a Character makes or brings remains ordinary Action introduction.

The [accepted build plan](../../plans/20260814-204007-first-investigation-discovery-loop/plan.md)
owns execution and the evidence boundary. The [live discovery record](../../../docs/concept/discovery.md#selected-planning-edge)
owns current rationale. The baseline ladder is green, but T0 waits for the User to
commit the complete uniform-state build; no discovery behavior is executable yet.

## Why ordered next

World entry, exact-Place orientation, Actions, Interactions, Properties and Traits
are delivered. The missing defining game outcome is World-authoritative discovery:
uncertainty resolved before Agent authorship and one accepted result shared through
current state and history. The former separate roll and commit rows would each stop
short of that player/World outcome, so the User selected one complete loop for
planning. It is `Next / Proposed` behind the active Sol-medium validation; the
draft plan is fully resolved and awaits explicit acceptance.

## Confirmed direction

- one complete loop is the selected next discovery outcome; it is currently
  the selected `Now / Blocked` edge, and roll and commit are not separate delivery milestones;
- pre-existing things are found through investigation and roll; made, brought or
  placed things remain ordinary Action introduction; the first result is one found
  Entity at the exact current Place with Agent-authored Properties and Traits;
- the start needs no User confirmation; the authored find is previewed and committed
  only after explicit confirmation;
- attempts are durable technical rows (attempt id as authority, no secrets); chance
  is an owned saturation component over recent finds at the Place; admission is a
  bounded per-User rate plus hoarding rule; zero writes no Activity;
- the Agent asks to investigate and World performs exactly one authoritative chance
  roll only after admitting the established context; callers never select seed,
  odds, result count or retry count;
- a fresh admitted request may roll even when World-state is unchanged and a prior
  attempt returned zero; equal idempotency is the same attempt;
- several attempt-specific, scope-bound positive tokens may coexist across
  conversations, while one Character-wide operational admission policy prevents
  conversation count from increasing throughput;
- World derives Character and exact Place and resolves before Agent content;
- the Agent authors semantic candidate content, while World remains deterministic
  and strict;
- technical retry is not a new attempt, and time/misses never improve odds;
- no durable Agent session, pending-opportunity stockpile, generic Discovery object,
  pity, score, movement, background work or server-side model enters the slice;
- one positive attempt may commit at most one result in the first slice;
- World, HTTP and MCP parity plus same-transaction attributable history are required;
- the plan is accepted and baseline verification passed; `docs/game/` and the
  thirteen-capability executable surface remain unchanged until the verified
  uniform-state baseline is committed and T0 completes.

## Dependencies

- delivered exact-Place Entity, Activity and current Property/Trait reads;
- delivered Character-grounded Action/Interaction and atomic Activity history;
- a committed clean baseline including the uniform Entity-state build, with a
  PostgreSQL-backed full-suite run;
- the completed Sol-medium validation edge.

## Non-goals

Movement, further Places (discovering a new Place is the named second result kind
for the movement edge), adjacency/containment, geometry, several results per
attempt, World-typed kinds or rich flora/fauna/material models, generic
events/observations, semantic inference, server-authored prose, signed tokens or
secrets, runtime-tunable parameters, auth, production rate-limiting infrastructure,
paid-model validation and Trait live revalidation.
