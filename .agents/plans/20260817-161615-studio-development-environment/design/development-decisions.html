Studio as the seamless development environment — proposed

proposed development environment

The User found that the delivered unified Studio does not yet give the overview needed to step back and redirect a builder: what player Agents receive, models and their relations, decided versus open choices, work in progress, experiments and the live World are not visible together, and Studio upkeep must never be a chore separate from repository upkeep.

planStudio concept
decided D1 rendering

The User chose Rust server-rendered pages with one stable path route per Studio resource over extending the just-delivered browser application. Reason: reload, history, sharing and copying work without browser state, every page is provable in cargo test, one resource costs one handler plus template, and Rust keeps all application logic.

affects src/studio, web, Studio tests, local-play contract
